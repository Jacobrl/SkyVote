# SkyVote: Project Brief for Claude Code

SkyVote is a community-built astronomy calendar, starting with full moons. It's a passion project I'm building in public to learn what it takes to own a product end to end. Each month, the community votes on LinkedIn and Instagram for the next feature.

## What I need help with now

Set up the foundation of the repo. Do these in order, and check with me after each one:

1. **Repo structure.** Initialise the repo with a simple layout for a static site, a `.gitignore`, and a `docs/` folder. Ask me before choosing a license.
2. **README.md.** One page, skimmable. Use only the content below. Ask before adding any other section.
3. **docs/requirements.md.** A one-page requirements doc built from the must-haves below. Don't add features I haven't listed.

The static site itself comes next week. Don't build site code yet unless I ask.

## README content

- **Title and tagline:** SkyVote: a community-built astronomy calendar, starting with full moons.
- **Why:** A passion project I'm building in public to learn what it takes to own a product end to end, shaped by what the community votes for.
- **How voting works:** Each month I post the same poll on LinkedIn and Instagram, add up the votes from both, and the top feature gets built next.

## Requirements: the seven must-haves

1. A page showing the next full moon with a countdown.
2. A list of this year's full moons with their dates.
3. Each full moon's traditional name and a short story behind it.
4. A link to the source for the dates, such as NASA or the US Naval Observatory.
5. A static site with no logins, accounts or AI chat yet.
6. No cookies or data collection at launch, plus a short privacy page saying so.
7. Moon name stories written in my own words, with sources credited.

Out of scope for launch: meteor showers, eclipses, AI chat, user accounts and voting on the site itself (voting happens on LinkedIn and Instagram).

## Rules from my personal AI policy

- **Astronomy, not astrology.** Keep all facts scientifically accurate. If astrology ever wins a vote, label it clearly as astrology, not science.
- **Facts need sources.** Never invent dates, figures or moon name stories. Flag anything you're unsure of so I can check it.
- **No secrets in the repo.** No passwords, API keys or anyone's personal data in code, commits or files.
- **Only my own work.** Don't copy text from other sites. Write stories in plain original words and credit sources.
- **Disclose AI in commits.** When you write code or content, note it in the commit message, for example: `Add README (drafted with Claude Code, reviewed by Jacob)`.
- **Dilemma test:** Would I be comfortable if a recruiter, a voter and a NASA scientist all saw how this was done? If not, stop and ask me.

## Audience

- **Site visitors:** friends and curious stargazers. Plain language, no jargon in the main text. Technical terms like "synodic month" belong in a "learn more" section, if anywhere.
- **Recruiters on GitHub:** they care that I shipped and kept going. Keep the repo tidy, the commit history clear and the README easy to skim.
